1这是什么

Competitor Watch 是一个游戏竞品自动化监测工具：把你关注的竞品游戏配置进一份 JSON，它会自动从多个渠道抓取动态、按多维度规则打分、生成日报/周报/月报，并可推送到腾讯文档或企业微信群。

  • 多渠道：微信公众号、TapTap 评论评分、好游快爆评分公告、官网/官方论坛
  • 多维度评分：9 个维度 × 权重，关键词规则引擎（无需 LLM），每个维度附 1–5 分判分标准
  • 多品类：MMO / SLG / 卡牌 / 开放世界 RPG 等，通过竞品的 genre 标签区分
  • 零第三方依赖：仅需 Python 3.10+，全部脚本只用标准库
💡 本工具面向任何 AI 助手 手册里的每条命令都是普通 Python 命令。无论你用 Claude、ChatGPT、Gemini、WorkBuddy 还是其他任何 AI 编码助手，把本 skill 目录发给它并引用 SKILL.md，它就能按手册执行。

25 分钟上手

前置要求

  • Python 3.10 或更高版本（python --version 可验证），无需安装任何第三方包
  • 所有命令都在 skill 根目录（即本文件所在目录）下执行

Step 1 · 准备配置文件

仓库自带一份 MMO 示例配置，复制即可运行：

# Windows（PowerShell） Copy-Item config\mmo-example.json config\competitor-watch.json # macOS / Linux cp config/mmo-example.json config/competitor-watch.json

也可以直接用本面板：在左侧各页签里编辑，到「系统配置」页签点「导出配置」下载 competitor-watch.json，放到 config/ 目录下。

Step 2 · 解析竞品入口

python scripts/resolve.py

自动为每个竞品定位好游快爆 fid、已在 RSS 服务订阅的公众号自动匹配 mp_id。游戏官网条目也是自动配置的——每个新竞品都会自动生成官网条目，无需手动填任何 URL。

Step 3 · 采集数据

python scripts/ingest.py # 全部数据源 python scripts/ingest.py --source hykb # 只跑好游快爆（无需任何密钥）
✅ 好游快爆源开箱即用 不配置任何密钥，hykb 源也能抓到每个竞品的评分与更新公告，足够跑通完整流程。微信公众号源需要自建/订阅 RSS 聚合服务（见第 4 节）。

Step 4 · 生成报告

python scripts/report.py daily # 昨天的日报（默认） python scripts/report.py daily --date 2026-06-02 python scripts/report.py weekly # 上周周报

报告输出到 data/reports/daily|weekly|monthly|yearly/<日期>.md。完成后可用 python scripts/publish.py daily 推送到腾讯文档/企微（需先在配置中开启）。

⚠️ 采完数据没有评分？ ingest 会在入库后自动打分；如果分数缺失，手动跑一次 python scripts/score.py 即可（幂等，只补未打分的文章）。

3配置详解

所有配置集中在一个文件：config/competitor-watch.json。分 5 个节（section）：

节管什么关键字段
games竞品列表（你最主要维护的）name（唯一）、aliases 别名、genre 品类、priority 优先级、type=industry 行业号
sources数据源接入wcrss.feed_url 微信 RSS 地址、fetch_defaults 抓取窗口
project我的项目（评分参照系）enabled 开关、name/genre/stage 画像、core_systems 等七组关键词字段、knowledge 项目概要（知识库）
scoring评分体系dimensions（含每维度 1–5 分标准 criteria、project_refs 项目字段引用）、weights 权重、tiers 评级档位
publish发布渠道tencent_docs 腾讯文档、wecom_bot 企微机器人、local_backup 本地输出
report报告格式content_tags 文章分类关键词、limits 长度截断、kind_titles 标题
💡 三种编辑方式任选 ① 用本面板各页签编辑后导出；② 直接用文本编辑器改 JSON；③ 让 AI 助手帮你改（"帮我把原神加进竞品列表"）。改完 games 后记得重跑 resolve.py。

敏感信息（RSS token、webhook、access_token）优先走环境变量：WCRSS_FEED_URL、TDOC_ACCESS_TOKEN、WECOM_WEBHOOK_URL。config/competitor-watch.json 已被 .gitignore 排除，请勿提交到公开仓库。

4数据源说明

三类数据源均可在「数据源」页签用 checkbox 开关自由启停（写入统一配置 sources 节）。关闭的渠道 ingest.py 采集时和 resolve.py 解析时都会自动跳过；重新开启后重跑一次 resolve.py 即可恢复。

渠道开关位置自动化程度数据类型与接入方式
wechat 微信公众号sources.wcrss.enabled半自动文章正文。需自建/订阅 RSS 聚合服务，地址填 sources.wcrss.feed_url（留空自动跳过，不影响其他源）
official 游戏官网sources.official.enabled自动配置公告 / RSS 快照。游戏列表更新后由 resolve.py 自动生成条目，无需手动接入（见下方说明）
hykb 好游快爆sources.extra_sources[]全自动评分 + 更新公告。resolve.py 自动搜索定位 fid，零配置
taptapsources.extra_sources[]半自动评分快照。resolve.py 生成占位 + _hint 搜索链接，按提示补 app_id 到 derived/taptap.json
自定义源（扩展）sources.extra_sources[]自定义在「数据源」页签添加条目 + 在 scripts/sources/ 放同名 <id>.py 采集器（提供 run() 函数），ingest.py 自动发现执行
✅ 游戏官网是自动配置的 你只需维护「游戏列表」：新增/修改竞品后重跑 python scripts/resolve.py，官网源会自动为每个新竞品生成条目（写入 config/derived/official.json），已有条目的 rss / selectors 配置原样保留。url 为空的占位条目在采集时自动跳过、不会报错；想升级为真正的公告抓取时，再给该条目补 rss 或 selectors 字段即可。
💡 扩展新数据源（如 B站 / 贴吧） ① 在「数据源 → 其他数据源」页签添加条目（源 ID + 显示名）；② 在 scripts/sources/ 目录新建与 ID 同名的 Python 文件，实现 run(**kwargs) -> (new, dup)（参考同目录 hykb.py，全部用标准库）；③ 打开条目开关即可。无需改动任何现有脚本。

新增竞品标准流程：① 改配置 games 数组加一行 → ② python scripts/resolve.py（官网条目自动生成、hykb fid 自动定位、公众号自动匹配）→ ③ python scripts/ingest.py → ④ python scripts/report.py daily。RSS 服务新增公众号订阅必须先经你确认，agent 不得自行下单。

5评分体系与标准

每篇文章按 关键词命中规则在各维度上打 1–5 分（起始 3 分中性，命中加分词上调、命中减分词下调，再叠加来源倾向），乘以权重求和得到总分，最后按档位（S/A/B/C/D）评级。

评分参照系（我的项目）：评分不是真空进行的——「评分体系」页签第一个卡片「我的项目」是你的产品画像（核心系统、目标用户、挂载模块、商业化模型、运营节奏、差异化方向、风险红线，外加一段项目概要知识库）。勾选启用后，各维度 project_refs 引用的字段会自动展开为该维度的打分关键词：改产品画像一处，七个维度的打分口径自动跟随；关闭后退化为纯通用关键词评分。每份报告的文件头都会标注当时的评分参照系，并附快照注释供回溯。

8故障排查 FAQ

症状排查步骤
ingest 无数据先看数据源开关：该渠道是否已在「数据源」页签开启；再查 config/derived/ 各文件是否有有效 id；hykb 源看控制台是否 fid 缺失；wechat 源确认 feed_url 有效
某源采集报错单源不影响其他源（ingest 逐源捕获异常）。可先在「数据源」页签关闭该源开关，其余源继续工作；修复后重新开启并重跑 resolve.py
官网源没数据属正常：url 为空的占位条目会自动跳过。给 derived/official.json 对应条目补 url（或 rss / selectors）后即可采集
报告全空该日期确实没有文章属正常；也可查 data/articles.db（sqlite）确认库里有数据
评分全是 C/D若「我的项目」未启用，先去「评分体系」页签启用参照系并填写产品画像；若已启用，检查 scoring.dimensions 关键词与 project 字段是否匹配你的品类
改了「我的项目」后评分没变存量文章需重打：跑 python scripts/score.py --rescore-all，再重新生成报告
publish 报错腾讯文档：检查 token 过期 / root_folder_id；企微：检查 webhook URL 是否有效
公众号 missing去 RSS 服务后台添加订阅 → 重跑 resolve.py（订阅操作需你本人确认）
想改报告版式编辑配置 report 节（章节顺序、分类关键词、标题文案），即时生效

📡微信公众号 RSS 半自动
需要一个聚合你所有公众号订阅的 RSS 服务（如自建 wechat2rss / wewe-rss 等），把聚合 Feed 地址（含 token）填入。环境变量 WCRSS_FEED_URL 优先级更高。关闭开关或留空 URL 时自动跳过本源，其余数据源不受影响。
🌐游戏官网 / 官方论坛 自动配置
官网条目无需手动配置：每当你在「游戏列表」页签新增/修改竞品并重跑 python scripts/resolve.py，本源会自动为每个新竞品生成官网条目（config/derived/official.json），已有条目的配置原样保留。
💡 官网源工作方式 ① 新增竞品 → 重跑 resolve.py → 自动生成条目占位（url 为空时采集阶段自动跳过，不报错）；② 想要真正的公告抓取，可给条目补 rss（站点 RSS 地址）或 selectors（CSS 选择器）字段；③ 重新开启本开关后重跑一次 resolve.py 即可恢复。
🧩其他数据源
可扩展的采集渠道列表，每条可独立开关。内置好游快爆 / TapTap 两个示例；要接入新渠道（B站、贴吧、小红书…），在下方添加条目，并在 scripts/sources/ 目录放一个与 id 同名的采集器脚本（提供 run() 函数），ingest.py 会自动发现并执行。入口 id（fid / app_id 等）由 resolve.py 自动维护在 config/derived/。
➕ 添加自定义数据源
🎯我的项目
你的产品画像——整个评分体系的参照系（配置 project 节）。勾选启用后，下方各维度 project_refs 引用的字段会自动展开为打分关键词；下方「项目概要」是提炼过的知识库，供 AI 工具分析报告时阅读理解项目背景。产品方向调整时只改这里，评分口径自动跟随（改完建议重跑 score.py --rescore-all）。
依赖提示：内置维度中 A 战略契合（核心系统）、B 用户匹配（目标用户）、C 玩法可迁移（挂载模块）、E 周期合理（运营节奏）、F 差异化（差异化方向）、G 付费拉动（商业化模型）、I 风险等级（风险红线）比较依赖本栏目；未启用时这些维度仅按通用关键词打分。
🧩 可挂载模块清单 （C 玩法可迁移维度对照：竞品玩法能直接挂到这些模块上即给高分）
⚖️评分维度
写入统一配置 scoring.dimensions。每个维度包含：名称、ID、权重（0–3）、衡量说明（desc）、1–5 分判分标准（criteria，供人工核对与 AI 理解）、引用项目字段（project_refs，启用「我的项目」后自动展开为关键词）、加分/减分通用关键词（引擎实际打分依据）。维度数量可自由增减，脚本自动适配。
➕ 添加新维度

总分（各维度得分×权重之和）落到哪一档。档位名与阈值可自定义，报告与评分脚本自动适配。

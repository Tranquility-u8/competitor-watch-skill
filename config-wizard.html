1这是什么

Competitor Watch 是一个游戏竞品自动化监测工具：把你关注的竞品游戏配置进一份 JSON，它会自动从多个渠道抓取动态、按多维度规则打分、生成日报/周报/月报，并可推送到腾讯文档或企业微信群。

  • 多渠道：微信公众号、TapTap 评论评分、好游快爆评分公告、官网/官方论坛
  • 多维度评分：9 个维度 × 权重，关键词规则引擎（无需 LLM），每个维度附 1–5 分判分标准
  • 多品类：MMO / SLG / 卡牌 / 开放世界 RPG 等，通过竞品的 genre 标签区分
  • 零第三方依赖：仅需 Python 3.10+，全部脚本只用标准库
💡 本工具面向任何 AI 助手 手册里的每条命令都是普通 Python 命令。无论你用 Claude、ChatGPT、Gemini、WorkBuddy 还是其他任何 AI 编码助手，把本 skill 目录发给它并引用 SKILL.md，它就能按手册执行。

25 分钟上手

前置要求

  • Python 3.10 或更高版本（python --version 可验证），无需安装任何第三方包
  • 所有命令都在 skill 根目录（即本文件所在目录）下执行

Step 1 · 准备配置文件

仓库自带一份 MMO 示例配置，复制即可运行：

# Windows（PowerShell） Copy-Item config\mmo-example.json config\competitor-watch.json # macOS / Linux cp config/mmo-example.json config/competitor-watch.json

也可以直接用本面板：在右侧各页签里编辑，到「导入 / 导出」页签下载 competitor-watch.json，放到 config/ 目录下。

Step 2 · 解析竞品入口

python scripts/resolve.py

自动为每个竞品定位好游快爆 fid、生成官网/TapTap 占位配置；已在 RSS 服务订阅的公众号会自动匹配 mp_id。

Step 3 · 采集数据

python scripts/ingest.py # 全部数据源 python scripts/ingest.py --source hykb # 只跑好游快爆（无需任何密钥）
✅ 好游快爆源开箱即用 不配置任何密钥，hykb 源也能抓到每个竞品的评分与更新公告，足够跑通完整流程。微信公众号源需要自建/订阅 RSS 聚合服务（见第 4 节）。

Step 4 · 生成报告

python scripts/report.py daily # 昨天的日报（默认） python scripts/report.py daily --date 2026-06-02 python scripts/report.py weekly # 上周周报

报告输出到 data/reports/daily|weekly|monthly|yearly/<日期>.md。完成后可用 python scripts/publish.py daily 推送到腾讯文档/企微（需先在配置中开启）。

⚠️ 采完数据没有评分？ ingest 会在入库后自动打分；如果分数缺失，手动跑一次 python scripts/score.py 即可（幂等，只补未打分的文章）。

3配置详解

所有配置集中在一个文件：config/competitor-watch.json。分 5 个节（section）：

节管什么关键字段
games竞品列表（你最主要维护的）name（唯一）、aliases 别名、genre 品类、priority 优先级、type=industry 行业号
sources数据源接入wcrss.feed_url 微信 RSS 地址、fetch_defaults 抓取窗口
scoring评分体系dimensions（含每维度 1–5 分标准 criteria）、weights 权重、tiers 评级档位、mount_points 挂载模块
publish发布渠道tencent_docs 腾讯文档、wecom_bot 企微机器人、local_backup 本地输出
report报告格式content_tags 文章分类关键词、limits 长度截断、kind_titles 标题
💡 三种编辑方式任选 ① 用本面板各页签编辑后导出；② 直接用文本编辑器改 JSON；③ 让 AI 助手帮你改（"帮我把原神加进竞品列表"）。改完 games 后记得重跑 resolve.py。

敏感信息（RSS token、webhook、access_token）优先走环境变量：WCRSS_FEED_URL、TDOC_ACCESS_TOKEN、WECOM_WEBHOOK_URL。config/competitor-watch.json 已被 .gitignore 排除，请勿提交到公开仓库。

4数据源说明

渠道自动化程度数据类型接入方式
hykb 好游快爆全自动评分 + 更新公告resolve.py 自动搜索定位 fid，零配置
wechat 微信公众号半自动文章正文需自建/订阅 RSS 聚合服务，把聚合地址填入 sources.wcrss.feed_url
taptap半自动评分 + 评论在 config/derived/taptap.json 为每个竞品补 app_id（resolve 会给出搜索链接提示）
official 官网/论坛手动配置链接快照 / RSS在 config/derived/official.json 填 url（支持 rss / CSS selectors）

新增竞品标准流程：① 改配置 games 数组加一行 → ② python scripts/resolve.py → ③ python scripts/ingest.py → ④ python scripts/report.py daily。RSS 服务新增公众号订阅必须先经你确认，agent 不得自行下单。

5评分体系与标准

每篇文章按 关键词命中规则在 9 个维度上各打 1–5 分（起始 3 分中性，命中加分词上调、命中减分词下调，再叠加来源倾向），乘以权重求和得到总分，最后按档位（S/A/B/C/D）评级。以下是当前配置的维度与判分标准（随「评分体系」页签的修改实时更新）：

6报告与发布

报告生成命令覆盖范围与内容
日报report.py daily昨天 00:00–24:00（CST）严格按发布时间过滤；概览 / 摘要（评分分层+分类汇总）/ 原文清单
周报report.py weekly上周一~周日；日报内容 + TOP 事件 + 评分趋势
月报 / 年报report.py monthly / yearly上月 / 去年；长周期趋势对比
补齐report.py daily --catch-up 7补齐过去 7 天缺失的日报，幂等安全

发布（publish.py）：本地 Markdown 恒开；腾讯文档按 (类型, 日期) 一份独立文档、同日期重跑为覆盖刷新、可按月归档到子文件夹；企微机器人推送摘要卡片，高信号事件 @all。正式推送前建议先 --dry-run 预览。

7日常使用（AI 指令速查）

把下面任意一句话发给你的 AI 助手（需能访问本目录）：

你说AI 会做
"拉一下今天的竞品动态"ingest → report daily → 展示高信号事件
"出个竞品周报"report weekly（自动取上周）
"把 XX 加进竞品监测"改配置 games → resolve → ingest 验证
"竞品评分最近怎么样"读 data/reports/ 或跑 score.py 统计
"把日报推到腾讯文档"publish daily（先 dry-run 确认再推）

定时节奏建议：每个工作日 12:00 跑 ingest + report daily --catch-up 3 + publish daily --catch-up 3；每周一加跑 weekly；每月 1 日加跑 monthly。

8故障排查 FAQ

症状排查步骤
ingest 无数据检查 config/derived/ 各文件是否有有效 id；hykb 源看控制台是否 fid 缺失；wechat 源确认 feed_url 有效
报告全空该日期确实没有文章属正常；也可查 data/articles.db（sqlite）确认库里有数据
评分全是 C/Dscoring.dimensions 的关键词与你的品类不匹配——在「评分体系」页签调整关键词与权重
publish 报错腾讯文档：检查 token 过期 / root_folder_id；企微：检查 webhook URL 是否有效
公众号 missing去 RSS 服务后台添加订阅 → 重跑 resolve.py（订阅操作需你本人确认）
想改报告版式编辑配置 report 节（章节顺序、分类关键词、标题文案），即时生效

📡微信公众号 RSS 服务
写入统一配置 sources 节。需要一个聚合你所有公众号订阅的 RSS 服务（如自建 wechat2rss / wewe-rss 等），把聚合 Feed 地址（含 token）填入。环境变量 WCRSS_FEED_URL 优先级更高。留空则跳过微信源，其余源不受影响。
ℹ️其余数据源
TapTap / 好游快爆 / 官网的入口配置由 resolve.py 自动维护在 config/derived/ 目录，无需在本面板填写。好游快爆全自动；TapTap 需按提示补 app_id；官网需在 derived/official.json 里补 URL。详见「用户手册」第 4 节。
⚖️评分维度
写入统一配置 scoring.dimensions。每个维度包含：名称、ID、权重（0–3）、衡量说明（desc）、1–5 分判分标准（criteria，供人工核对与 AI 理解）、加分/减分关键词（引擎实际打分依据）。维度数量可自由增减，脚本自动适配。
➕ 添加新维度
📊评级档位（Tiers）
总分（各维度得分×权重之和）落到哪一档。档位名与阈值可自定义，报告与评分脚本自动适配。
🧩挂载模块（自家产品清单）
你的产品有哪些现成可挂载的系统？用于「玩法可迁移性」维度对照：竞品玩法能直接挂到这些模块上，该维度即给高分。
💾本地输出 默认开启
